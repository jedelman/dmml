# 2026-09-19 — The prose, wired in

Jason: *"Show me the prose! Then wire the catalog into the driver so Jev reads prose;
then let's build those templates!"*

## The prose

`render-prose` — the runtime half of what `check-prose-coverage` measures, through the
identical path: same catalog, same `eligibleTemplates` (real `evalGuards`), same
`renderTemplateWith`. Nothing selects or generates; a template is eligible or it is not
and its text is fixed, so two runs over one world give the same sentences.

```
keeper/orrin  (Orrin Fell, Lock Keeper)
    Orrin Fell, Lock Keeper stands at Stillwater Lock Station.
    Orrin Fell, Lock Keeper quarters at Keeper's Quarters.
    Orrin Fell, Lock Keeper keeps The Lock Chamber, and it is theirs to keep.
    Orrin Fell, Lock Keeper holds The Gatehouse Key.
mast/signal  (The Signal Mast)
    The Signal Mast stands at Stillwater Lock Station.
    The Signal Mast shows signal/dark.
```

## Fallback markers, because one catalog has to serve two corpora

First render exposed a defect the coverage number could not: `{attr:at}` gives *"stands
at station/stillwater"* in a world whose places are named, and `{attr:at.name}` leaves a
literal brace in a world whose places are not. **Neither marker is right for both**, and
a catalog that forks per corpus is not canonical.

The obvious fix — two templates, one guarded on the object having a name — **is not
expressible.** `guard self \`at\` ?p \`name\` ?n` parses fine (multi-hop patterns are
real) and never matches, because `name` is literal-valued and `DMML.Guard` excludes
literal-valued facts from a guard walk.

**That constraint bit three separate times today**, which is how it earned a name:
literal-valued predicates cannot be covered by their own guard; a literal cannot make a
template eligible; and now, a literal cannot even be tested for existence. **Guards see
the node-valued skeleton of a graph. Nearly everything a reader wants to say hangs off it
as literals.**

So the fix goes in rendering, where it belongs: `{attr:at.name|at}` — alternatives tried
left to right, first that resolves wins. It changes what is *said* and never what is
*true*, and a single-path marker behaves exactly as before.

## The catalog: 65 templates, every node-valued predicate covered

```
205 of 244 live facts covered by 65 templates
UNCOVERED, literal-valued -- NO guard can ever match these:  14 predicates
```

The node-valued section is **empty**. What remains is the literal class, and the report
now says why rather than asking for something impossible.

## Wired into the driver

`describe_frontier_node` and `build_state_summary` now read sentences. What Jev sees,
round 1, live:

> 4 way(s) stand open with nothing built beyond them. way/north — What comes off
> way/north is sound/none. way/north has draft/cold about it. way/east — What comes off
> way/east is sound/echo. way/east has water/running about it. …

Rendered once per round, not per lookup — `render-prose --json` over the whole world in
one call, which is the `scan-candidates` lesson applied again. **Fails soft**: a missing
binary or a bad catalog leaves the map empty and every describer falls back to the raw
triple, because a run that loses its prose should read worse, not stop.

## And it changed nothing, which is the honest result

Round 1 frontier interest reading **prose**: `way/west 0.57, way/east 0.50, way/north
0.26, way/south 0.26`. Reading **triples**, the same round earlier: `0.56 / 0.51 / 0.28 /
0.25`.

Identical within noise. Which makes sense and is worth stating plainly: **cannon-fanout's
vocabulary was already English.** `has draft/cold` and *"way/north has draft/cold about
it"* carry the same information to a reader. The prose layer earns its keep exactly where
the triple stops reading — `upstreamOf weir/low`, `apprenticesUnder master/iolo` — and
this demo world has none of those.

The value delivered here is not a better score on this run. It is that the description
path is now the measured one, so a world whose predicates are *not* English verbs will
read correctly without anyone noticing it had stopped.

## Still open

- **14 literal-valued predicates.** Needs per-world eligibility or a `DMML.Guard` spec
  change, which its haddock says is faithful to the real crate — a spec question, not a
  patch.
- **`{subject} is type/keeper`** — type nodes carry no `name` fact, so the fallback lands
  on the raw node. A world problem, not a template one, but it is the ugliest sentence in
  the output.
- Only `cannon-fanout` has a catalog wired. The other three demos still read triples.
